# Conduit Desktop App

`desktop/` is the Wails v2 macOS app. It starts the gateway inside its own
process and points a native window at the admin panel.

## It is a separate Go module, and it must stay one

`desktop/go.mod`:

```
module github.com/serbansorin/conduit/desktop

go 1.25.0

require (
	github.com/serbansorin/conduit v0.0.0
	github.com/wailsapp/wails/v2 v2.17.0
)
```

with the replace directive that points it at the parent:

```
replace github.com/serbansorin/conduit => ../
```

The reason is in `desktop/README.md`:

> `desktop/` is a separate Go module. The Wails dependency stays out of the
> root module on purpose: the root module is also built as a Linux container
> image, and Wails needs desktop toolkit headers that would break that build.

**Never add Wails to the root `go.mod`.** The root `Dockerfile` builds with
`CGO_ENABLED=1 GOOS=linux` against `golang:1.25-alpine`. Wails pulls in
desktop toolkit headers that do not exist there. The root CI workflow also
excludes the desktop directory from the formatting gate
(`gofmt -l . | grep -v '^desktop/'`) and `go build ./...` from the root never
compiles `desktop/`.

The reverse is also true: the root module must never import anything from
`desktop/`.

## The files

| File | Responsibility |
| --- | --- |
| `desktop/main.go` | the Wails entry point. Builds `options.App`, calls `wails.Run`. |
| `desktop/app.go` | the `App` struct, the panel handoff page, the methods bound to the frontend. |
| `desktop/gateway.go` | the app data directory, the generated credentials, starting the gateway, the admin login. |
| `desktop/menu.go` | the native application menu. |
| `desktop/wails.json` | the Wails project configuration. |
| `desktop/frontend/` | a static loading screen. Not the panel. |

### `main.go`

`wails.Run(&options.App{...})` with:

- `Title: appTitle` (which is `"Conduit"`), `Width: 1440`, `Height: 900`,
  `MinWidth: 1024`, `MinHeight: 700`.
- `AssetServer: &assetserver.Options{Handler: http.HandlerFunc(app.servePanel)}`.
- `Menu: app.buildMenu()`.
- `OnStartup: app.startup`, `OnShutdown: app.shutdown`.
- `Bind: []interface{}{app}`.

`app, err := newApp()` runs first. A failure prints `conduit: %v` to stderr
and exits 1.

### `app.go`

```go
type App struct {
	ctx        context.Context
	baseURL    string
	adminURL   string
	adminToken string
	cancel     context.CancelFunc
}
```

Methods:

| Method | Exported | Bound to the frontend |
| --- | --- | --- |
| `newApp() (*App, error)` | no | no |
| `ensureDir(dir string) error` | no | no |
| `startup(ctx context.Context)` | no | no |
| `shutdown(ctx context.Context)` | no | no |
| `panelURL() string` | no | no |
| `servePanel(w http.ResponseWriter, r *http.Request)` | no | no |
| `OpenInBrowser()` | yes | yes |
| `OpenGitHub()` | yes | yes |
| `AdminURL() string` | yes | yes |
| `BaseURL() string` | yes | yes |

Wails binds only the exported methods. The generated bindings are in
`desktop/frontend/wailsjs/go/main/App.d.ts` and `App.js`:

```ts
export function AdminURL():Promise<string>;
export function BaseURL():Promise<string>;
export function OpenGitHub():Promise<void>;
export function OpenInBrowser():Promise<void>;
```

That directory is gitignored (`desktop/.gitignore` lists `frontend/wailsjs/`),
so it is regenerated by the Wails CLI. Do not hand-edit it.

`servePanel` answers every GET with the inline `redirectTemplate` constant, a
small HTML page that redirects to the panel URL:

```go
w.Header().Set("Content-Type", "text/html; charset=utf-8")
w.Header().Set("Cache-Control", "no-store")
_, _ = w.Write([]byte(strings.ReplaceAll(redirectTemplate, "{{URL}}", a.panelURL())))
```

### `gateway.go`

Constants:

```go
const (
	appTitle        = "Conduit"
	appDirName      = "conduit"
	credentialsFile = "admin.json"
	databaseFile    = "conduit.db"
	startupTimeout  = 30 * time.Second
)
```

`appDataDir()` returns `filepath.Join(os.UserConfigDir(), appDirName)`. On
macOS that is `~/Library/Application Support/conduit/`. The OS specific part
comes from `os.UserConfigDir()`, there is no branch in the code.

`ensureDir` creates the directory with mode `0700`.

The credentials file:

```go
type credentials struct {
	AdminPassword string `json:"admin_password"`
	JWTSecret     string `json:"jwt_secret"`
}
```

`loadOrCreateCredentials(dir)` reads `<dir>/admin.json` and reuses it when both
fields are non-empty. Otherwise it generates fresh values with `randomHex`:

- `AdminPassword: randomHex(16)` (32 hex characters).
- `JWTSecret: randomHex(32)` (64 hex characters).

The file is written with mode `0600`. `randomHex` uses `crypto/rand` and
panics if the system entropy source is broken.

Both values are mandatory. `config.ValidateSecurity()`, called at the top of
`server.Run`, refuses to start when `ADMIN_PASSWORD` is `admin`, when
`JWT_SECRET` is the built-in default, or when `JWT_SECRET` is shorter than 32
bytes. The desktop app sets both through the environment before starting the
gateway, so it never trips that check.

## Running the gateway in-process

`startGateway(dir string, creds *credentials) (*server.Result,
context.CancelFunc, error)` in `desktop/gateway.go` calls the parent module
directly, through the `replace` directive:

```go
os.Setenv("DB_PATH", filepath.Join(dir, databaseFile))
os.Setenv("ADMIN_PASSWORD", creds.AdminPassword)
os.Setenv("JWT_SECRET", creds.JWTSecret)

ctx, cancel := context.WithCancel(context.Background())
ready := make(chan *server.Result, 1)

go func() {
	_, err := server.Run(ctx, server.Options{
		Bind:           "127.0.0.1",
		UseRandomPort:  true,
		AsyncModelSync: true,
		OnReady:        func(result *server.Result) { ready <- result },
	})
	if err != nil {
		fmt.Fprintf(os.Stderr, "conduit: gateway stopped: %v\n", err)
	}
}()

select {
case result := <-ready:
	return result, cancel, nil
case <-time.After(startupTimeout):
	cancel()
	return nil, nil, errors.New("the gateway did not start within " + startupTimeout.String())
}
```

Points that matter:

- **Loopback only.** `Bind: "127.0.0.1"`. The desktop gateway is never
  reachable from the network.
- **Random port.** `UseRandomPort: true` makes `server.listen` skip both the
  configured port and the `9812` default, so the OS assigns a free port. Two
  desktop instances never collide.
- **Port discovery.** The `OnReady` callback receives a `*server.Result`.
  `Result.Addr` is `listener.Addr().String()` and `Result.BaseURL` is
  `"http://" + Addr`. `Result.AdminURL` is `BaseURL + "/admin"`.
- **Async catalogue sync.** `AsyncModelSync: true` so the window opens
  immediately while the model catalogue syncs in the background.
- **Timeout.** The app waits 30 seconds for the listener. `startupTimeout` is
  the only place that number lives.
- **Shutdown.** The returned `context.CancelFunc` is stored on the `App` and
  called from `shutdown`.

Because `config.Load()` runs once behind a `sync.Once`, the environment
variables must be set before `server.Run` touches `config.Get()`. Setting them
at the top of `startGateway` is what makes that work. Never move the
`os.Setenv` calls below the `server.Run` call.

The database lives next to the credentials as `conduit.db` in the same app
data directory.

## The `?token=` panel handoff

The desktop app logs in to its own admin API to get a session JWT, then hands
that JWT to the panel through the URL.

`adminLogin(baseURL, password string) (string, error)` posts to
`/admin/login`:

```go
body, _ := json.Marshal(map[string]string{"password": password})
resp, err := client.Post(baseURL+"/admin/login", "application/json", bytes.NewReader(body))
```

The response carries `{"token": "..."}`. The server side is `admin/router.go`
`login`: it checks the password against `config.Get().AdminPassword` with a
constant-time compare and signs an HS256 JWT with `role: admin`,
`iss: conduit`, `aud: admin` and a 12 hour expiry.

`panelURL` builds the handoff URL:

```go
func (a *App) panelURL() string {
	return a.adminURL + "?token=" + url.QueryEscape(a.adminToken)
}
```

So the final URL is:

```
http://127.0.0.1:<random-port>/admin?token=<url-escaped JWT>
```

The panel consumes it in `web/js/app.js`: the `token` query parameter is
read, stored in `localStorage` under `admin_token`, and stripped from the URL
with `history.replaceState` so it does not linger in the browser history.

If you add a panel parameter, follow the same pattern: read it once, store it,
strip it from the URL.

## The menu

`desktop/menu.go` `buildMenu() *menu.Menu`:

- Application submenu (`appTitle`): "Open in Browser" (Cmd+O), "Open GitHub"
  (Cmd+U), a separator, "Quit" (Cmd+Q).
- View submenu: "Reload Panel" (Cmd+R), "Toggle Fullscreen" (no accelerator).

`cmd(key string) *keys.Accelerator` builds the accelerator with
`keys.CmdOrCtrlKey`.

The menu calls the `App` methods directly in Go. It does not go through the
frontend bindings.

## The build

```bash
cd desktop && wails build
```

The bundle lands at `desktop/build/bin/conduit.app`.

Two different names are involved and they are easy to mix up:

- `desktop/wails.json` has `"name": "conduit"`. That is the **bundle** name,
  so the directory is `conduit.app`.
- `desktop/wails.json` has `"outputfilename": "Conduit"`. That is the
  **binary** name inside the bundle, so the executable is
  `desktop/build/bin/conduit.app/Contents/MacOS/Conduit`.

`desktop/wails.json` in full:

```json
{
  "$schema": "https://wails.io/schemas/config.v2.json",
  "name": "conduit",
  "outputfilename": "Conduit",
  "frontend:install": "npm install",
  "frontend:build": "npm run build",
  "frontend:dev:watcher": "npm run dev",
  "frontend:dev:serverUrl": "auto",
  "author": { "name": "Serban Sorin" },
  "info": {
    "companyName": "Conduit",
    "productName": "Conduit",
    "productVersion": "2.0.0",
    "copyright": "Copyright (c) 2026 Serban Sorin",
    "comments": "Multi-key LLM gateway — one endpoint, every model."
  }
}
```

`frontend:dir` is not set, so Wails uses the default `frontend` directory.

The frontend build is a copy, not a compile. `desktop/frontend/package.json`:

```json
"scripts": {
  "build": "node build.js",
  "dev": "node build.js --watch"
}
```

`desktop/frontend/build.js` copies every file from `frontend/src/` into
`frontend/dist/` and prints what it copied. Its own comment says it: "The
build step only exists to satisfy the Wails asset pipeline."

`frontend/src/index.html` is a static "CONDUIT / Starting the gateway..."
loading screen.

The dev loop:

```bash
cd desktop && wails dev
```

Note that `build.js` never reads `process.argv`, so the `--watch` flag in the
`dev` script does nothing. The script copies once and exits. Do not rely on
live reload.

## Traps

- Do not add Wails to the root `go.mod`. Do not import `desktop/` from the
  root module. The two modules must stay independent.
- `desktop/go.mod` requires the parent as `github.com/serbansorin/conduit
  v0.0.0` and relies on `replace ... => ../` to resolve it. Change the
  replace target and the desktop app stops finding `server.Run`.
- The environment variables for `DB_PATH`, `ADMIN_PASSWORD` and `JWT_SECRET`
  must be set before `server.Run`. `config.Load()` is a `sync.Once`.
- The gateway binds `127.0.0.1` on a random port. Never change `Bind` to an
  empty string: that binds every interface and exposes the gateway, its
  tokens and its key pool to the network.
- `main.go` sets `AssetServer.Options.Handler` without `Assets`, and there is
  no `//go:embed` directive anywhere in `desktop/`. The Wails asset server
  therefore forwards every GET to `app.servePanel`, and the window gets the
  inline `redirectTemplate`. The `frontend/dist` output is not served by the
  production binary. If you add a native page, serve it from `servePanel`,
  not from `frontend/dist`.
- After the redirect the panel is an ordinary HTTP page served by the
  gateway, so the Wails runtime is not present there. The bound methods are
  not callable from the panel. The native menu calls the Go methods directly.
- `desktop/.gitignore` excludes `build/bin/`, `frontend/node_modules/`,
  `frontend/dist/` and `frontend/wailsjs/`. The checked-in
  `desktop/build/bin/conduit.app` on disk is a local build artifact, not
  source.
- The desktop app is not built by CI. Verify a desktop change locally with
  `cd desktop && wails build`.

## Verify a change

```bash
export PATH="/opt/homebrew/bin:$PATH"
cd desktop && go build ./... && wails build
```

Then launch `desktop/build/bin/conduit.app` and confirm that the window
redirects to `http://127.0.0.1:<port>/admin?token=...` and that the panel
loads signed in.
